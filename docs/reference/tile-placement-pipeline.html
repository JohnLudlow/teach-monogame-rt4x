Tile placement pipeline

A compact pattern for making an RT4X map interaction durable: the player points in screen space, the game resolves the pointing position through the camera and grid, the world validates an action on a cell, and rendering derives pixels from that stored cell.

Pipeline

device state
  MouseState.LeftButton + (X, Y)
       │ edge: pressed now, released previously
       ▼
input command
  PlaceSettlementAtScreenCommand(ScreenPosition)
       │ Screen → Grid using the current Camera.Transform
       ▼
world rule
  TryPlace(Point cell)
  ├─ reject: cell is out of bounds
  ├─ reject: cell is occupied
  └─ accept: settlements.TryAdd(cell, new Settlement(cell))
       │ Grid → World rectangle
       ▼
render
  marker centred in GridToWorldRect(settlement.Cell)
  inside SpriteBatch.Begin(transformMatrix: camera.Transform)

Rules worth preserving

Store grid coordinates
A grid cell is stable while camera position and zoom change. Convert it to world coordinates only to draw or query geometry.
Use a press edge, not a held state
isDown && !wasDown emits one action per press. A held state repeats every update and needs a deliberately designed repeat policy.
Validate in the world system
The system rejects invalid or occupied cells even if the UI later tries to prevent them. The world rule remains true for clicks, AI, replay, or network commands.
Use one camera transform
Resolve a click with Grid.ScreenToGrid(screen, camera.Transform); draw markers in the sprite batch using that same transform. This keeps picking and rendering aligned through pan and zoom.
Draw from data, never store draw rectangles
GridToWorldRect(cell) is derived presentation data. Recompute it when drawing rather than letting presentation state become a second source of truth.

Minimal data shape

public sealed record Settlement(Point Cell);

private readonly Dictionary<Point, Settlement> _settlements = [];

public bool TryPlace(Point cell)
{
  if (!grid.IsValidGridPosition(cell)) return false;
  return _settlements.TryAdd(cell, new Settlement(cell));
}

The dictionary key expresses the one-settlement-per-cell rule. When the game later needs multiple layers (for example, a road plus a city), introduce separate occupancy rules deliberately rather than weakening this invariant accidentally.

Checklist when it fails

  • Is placement resolved with the same camera.Transform used by drawing?
  • Is the click an edge (down && !wasDown) rather than a held state?
  • Does the world system own bounds and occupancy validation?
  • Does the marker derive its rectangle from GridToWorldRect(settlement.Cell)?
  • Is the marker drawn within the transformed world sprite-batch block, not in screen-space UI?
