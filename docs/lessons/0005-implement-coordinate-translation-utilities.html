Lesson 0005 · 30 minutes

Implement coordinate translation utilities

Your grid prototype works with screen-space coordinates. As your game grows, you'll need multiple coordinate systems: input, screen, world, grid, and local entity spaces. This lesson guides you through building a reusable coordinate transformation system.

What you need to know

Read the coordinate systems and transforms reference first. This lesson focuses on implementation, not theory. The coordinate quiz can help you check your understanding before starting.

Key concepts from the reference:

  • Five coordinate systems: Input, Screen, World, Grid, Local
  • Camera transform moves World → Screen (invert for Screen → World)
  • Grid conversion: divide by cell size (world → grid) or multiply (grid → world)
  • Order matters for matrix multiplication (scale before translate)

Your exercise

Create coordinate translation utilities in FourxGame.MonoGame.Core. These will be the foundation for camera systems, input handling, and spatial logic throughout your game.

  1. Create the utility class
    Create a new class Transforms.cs in FourxGame.MonoGame.Core/. Add methods for all conversion directions.
  2. Implement Grid coordinate helpers
    Since you already have a Grid class, add extension methods or instance methods for:
    • GridToWorld(Vector2) — convert grid coordinates to world position
    • WorldToGrid(Vector2) — convert world position to grid coordinates
    • ScreenToGrid(Vector2) — convert screen position to grid coordinates
    • GridToScreen(Vector2) — convert grid coordinates to screen position
    Note: ScreenToGrid and GridToScreen will need a camera transform parameter.
  3. Implement Camera class
    Create a Camera class in FourxGame.MonoGame.Core/ with:
    • Transform matrix (World → Screen)
    • Position (world coordinates of camera center)
    • Zoom (scale factor, 1.0 = 1:1)
    • ViewportWidth and ViewportHeight
    • UpdateTransform() method to rebuild the matrix
  4. Implement Camera coordinate helpers
    Add methods to Camera:
    • WorldToScreen(Vector2) — apply transform
    • ScreenToWorld(Vector2) — invert transform
  5. Update the Grid class
    Add the origin as a Vector2 (already has Origin), and add grid dimensions:
    • Origin (Vector2, not Point — sub-pixel precision helps)
    • Width (number of columns)
    • Height (number of rows)
    • CellSize (int)
  6. Test the conversions
    In Game1.cs, add debug output or visual markers to verify conversions work correctly:
    • Hovering cell 0,0 should show world position equal to origin
    • Hovering cell 1,0 should be one cell size right of origin
    • Converting world position back to grid should return original cell

Common pitfalls

Division vs modulo
Grid coordinates use integer division (truncate), not modulo. Use (int)(x / cellSize), not x % cellSize.
Float precision
World positions should use Vector2 (float), not Point (int). Grid coordinates can be Vector2 or Point depending on whether you support sub-tile precision.
Matrix order
For camera: Matrix.CreateScale(Zoom) * Matrix.CreateTranslation(-Position.X, -Position.Y, 0) (scale first, then translate).
Bounds checking
After ScreenToGrid, validate that the result is within [0, Width) and [0, Height) before using as an array index.

Retrieval check

  2. When converting grid 0,0 to world, what should the result equal?
  3. Why must UpdateTransform be called after changing camera properties?
Show answers
  1. Matrix.Invert — transposes only for orthonormal matrices (rotation without scaling).
  2. GridToWorld(0,0) should equal the grid's origin position in world coordinates.
  3. Because the transform matrix is cached; changing properties doesn't automatically rebuild it.
