Lesson 1 — Verify the game loop

Your RT4X needs a reliable, continuously updated simulation. Before terrain, cities, or UI, prove that the subject repository can build and run one MonoGame window.

What you need to know

A MonoGame Game separates simulation from rendering: Update advances state and Draw displays that state. Read the frame-loop reference first; it is the rule we will preserve when game-speed controls arrive.

Your exercise

  1. Open monogame-rt4x in Visual Studio or VS Code. It currently contains an empty solution and pins .NET SDK 10.0.400.
  2. Follow MonoGame’s official Getting Started guidance to install its templates and create a DesktopGL project inside monogame-rt4x. Use the current MonoGame template rather than hand-writing project plumbing.
  3. Add the generated project to monogame-rt4x.slnx using your IDE or dotnet sln monogame-rt4x.slnx add <project-path>. Do not add game assets yet: the next setup lesson will follow the required content builder project approach instead of relying on an MGCB config file.
  4. Build it, then run it. You win when a window appears and closes cleanly via its normal close button.
  5. Open the generated game class. Find Update and Draw, then write one sentence for each without looking at the reference.

Fast feedback

From the subject root, run:

dotnet build monogame-rt4x.slnx
dotnet run --project FourxGame.MonoGame/FourxGame.MonoGame.csproj

dotnet build validates compilation; dotnet run launches the window. Both succeeding verify the toolchain and loop. If either fails, stop there and send me the exact command plus its output; do not troubleshoot by adding packages at random.

Retrieval check

Answer: Update. Drawing should only present the already-decided state.
