Lesson 6 · Architecture

Integrate Coordinate Utilities and Camera

Now that you understand coordinate systems, it's time to clean up the current architecture by creating proper utility classes and integrating them with your Grid class. This lesson will move you from inline coordinate math to a clean, reusable system.

The Current Problem

Your current Game1.cs has coordinate conversion logic scattered inline:

var hoveredCell = new Point(
  (mouseState.X - _gridOrigin.X) / _gridCellSize,
  (mouseState.Y - _gridOrigin.Y) / _gridCellSize
);

This approach has several issues:

  • No bounds checking — clicking outside the grid could cause exceptions later
  • Scattered coordinate math — conversion logic will be duplicated across your codebase
  • No camera system — you can't pan or zoom your view
  • Tight coupling — Game1 knows too much about grid coordinate math

The Solution: Three Classes

You'll create three focused classes that work together:

Transforms (static utility class)
Coordinate conversion methods that don't depend on any specific grid or camera instance
Camera (instance class)
Manages screen-to-world transformations, zoom, and pan state
Enhanced Grid (instance class)
Your existing Grid class, but with convenience methods for coordinate conversion and bounds checking

Implementation Steps

Step 1: Create the Transforms Utility Class

Create FourxGame.MonoGame.Core/Transforms.cs:

using Microsoft.Xna.Framework;

namespace FourxGame.MonoGame.Core;

public static class Transforms
{
    /// <summary>
    /// Convert screen coordinates to world coordinates using camera transform
    /// </summary>
    public static Vector2 ScreenToWorld(Vector2 screenPos, Matrix cameraTransform)
    {
        Matrix.Invert(cameraTransform, out Matrix inverseTransform);
        return Vector2.Transform(screenPos, inverseTransform);
    }

    /// <summary>
    /// Convert world coordinates to screen coordinates using camera transform
    /// </summary>
    public static Vector2 WorldToScreen(Vector2 worldPos, Matrix cameraTransform)
    {
        return Vector2.Transform(worldPos, cameraTransform);
    }

    /// <summary>
    /// Convert world coordinates to grid coordinates
    /// </summary>
    public static Point WorldToGrid(Vector2 worldPos, Vector2 gridOrigin, int gridCellSize)
    {
        var localX = worldPos.X - gridOrigin.X;
        var localY = worldPos.Y - gridOrigin.Y;
        return new Point(
            (int)Math.Floor(localX / gridCellSize),
            (int)Math.Floor(localY / gridCellSize)
        );
    }

    /// <summary>
    /// Convert grid coordinates to world coordinates (cell center)
    /// </summary>
    public static Vector2 GridToWorld(Point gridPos, Vector2 gridOrigin, int gridCellSize)
    {
        return new Vector2(
            gridOrigin.X + gridPos.X * gridCellSize + gridCellSize / 2f,
            gridOrigin.Y + gridPos.Y * gridCellSize + gridCellSize / 2f
        );
    }
}

Note the Math.Floor: This ensures negative coordinates map correctly to grid cells. Without it, (-1, -1) might map to grid cell (0, 0) instead of (-1, -1).

Step 2: Create the Camera Class

Create FourxGame.MonoGame.Core/Camera.cs:

using Microsoft.Xna.Framework;

namespace FourxGame.MonoGame.Core;

public class Camera
{
    public Vector2 Position { get; set; } = Vector2.Zero;
    public float Zoom { get; set; } = 1.0f;
    
    private Matrix _transform;
    private bool _transformNeedsUpdate = true;

    public Matrix Transform
    {
        get
        {
            if (_transformNeedsUpdate)
            {
                _transform = Matrix.CreateScale(Zoom) * Matrix.CreateTranslation(Position.X, Position.Y, 0);
                _transformNeedsUpdate = false;
            }
            return _transform;
        }
    }

    public void SetPosition(Vector2 position)
    {
        Position = position;
        _transformNeedsUpdate = true;
    }

    public void SetZoom(float zoom)
    {
        Zoom = Math.Max(0.1f, Math.Min(5.0f, zoom)); // Clamp zoom between 0.1x and 5.0x
        _transformNeedsUpdate = true;
    }

    public void Pan(Vector2 delta)
    {
        Position += delta;
        _transformNeedsUpdate = true;
    }
}

Design note: The lazy evaluation pattern for Transform avoids recomputing the matrix every frame unless position or zoom actually changed.

Step 3: Enhance the Grid Class

Update FourxGame.MonoGame.Core/Entities/Grid.cs:

using Microsoft.Xna.Framework;

namespace FourxGame.MonoGame.Core.Entities;

public class Grid
{
    public Vector2 Origin { get; set; } = Vector2.Zero;
    public required int GridCellSize { get; set; }
    public required int GridSizeX { get; set; }
    public required int GridSizeY { get; set; }

    /// <summary>
    /// Convert world position to grid coordinates
    /// </summary>
    public Point WorldToGrid(Vector2 worldPos)
    {
        return Transforms.WorldToGrid(worldPos, Origin, GridCellSize);
    }

    /// <summary>
    /// Convert grid coordinates to world position (cell center)
    /// </summary>
    public Vector2 GridToWorld(Point gridPos)
    {
        return Transforms.GridToWorld(gridPos, Origin, GridCellSize);
    }

    /// <summary>
    /// Check if grid coordinates are within bounds
    /// </summary>
    public bool IsValidGridPosition(Point gridPos)
    {
        return gridPos.X >= 0 && gridPos.X < GridSizeX &&
               gridPos.Y >= 0 && gridPos.Y < GridSizeY;
    }

    /// <summary>
    /// Convert screen position to grid coordinates via world space
    /// </summary>
    public Point? ScreenToGrid(Vector2 screenPos, Matrix cameraTransform)
    {
        var worldPos = Transforms.ScreenToWorld(screenPos, cameraTransform);
        var gridPos = WorldToGrid(worldPos);
        
        return IsValidGridPosition(gridPos) ? gridPos : null;
    }
}

Design note: ScreenToGrid returns null for out-of-bounds clicks, making it safe to use without additional bounds checking.

Step 4: Update Game1 to Use the New Architecture

Update your Game1.cs to use the new classes:

// Add these using statements
using FourxGame.MonoGame.Core;
using FourxGame.MonoGame.Core.Entities;

public class Game1 : Game
{
    // Replace individual grid variables with:
    private Grid _grid;
    private Camera _camera;
    private Point? _hoveredCell;

    // In Initialize():
    protected override void Initialize()
    {
        _grid = new Grid
        {
            GridCellSize = 48,
            GridSizeX = 32,
            GridSizeY = 16,
            Origin = Vector2.Zero
        };

        _camera = new Camera();

        base.Initialize();
    }

    // In Update():
    protected override void Update(GameTime gameTime)
    {
        if (GamePad.GetState(PlayerIndex.One).Buttons.Back == ButtonState.Pressed || 
            Keyboard.GetState().IsKeyDown(Keys.Escape))
            Exit();

        var mouseState = Mouse.GetState();
        var mousePos = new Vector2(mouseState.X, mouseState.Y);
        
        _hoveredCell = _grid.ScreenToGrid(mousePos, _camera.Transform);

        base.Update(gameTime);
    }

    // In Draw(), add camera transform:
    protected override void Draw(GameTime gameTime)
    {
        GraphicsDevice.Clear(Color.CornflowerBlue);

        _spriteBatch.Begin(transformMatrix: _camera.Transform);
        
        // Your existing grid drawing code here...
        
        _spriteBatch.End();

        base.Draw(gameTime);
    }
}

Test Your Implementation

Build and run your game. You should see:

  1. The same grid as before
  2. No runtime errors when clicking outside the grid bounds
  3. Clean coordinate conversion logic separated from game logic

Troubleshooting

If you get build errors about missing using statements or namespace issues, double-check that your using FourxGame.MonoGame.Core; statements are present and match your project structure.

  • Built camera foundation: Ready for zoom and pan features
