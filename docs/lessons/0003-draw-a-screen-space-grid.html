Lesson 0003 · 20 minutes

Draw the first top-down strategy grid

Your mission is a maintainable fantasy RT4X prototype, not a blue window forever. Before terrain generation or units, give the game a visible map structure: a simple top-down grid drawn entirely from code.

What you need to know

MonoGame's SpriteBatch can draw a texture into any destination rectangle, which means one 1x1 white pixel can become every grid line once it is scaled and tinted. A Texture2D can also be created in code and populated with SetData, so this lesson needs no imported art. Read the screen-space grid recipe first; it keeps rendering separate from simulation, just like the frame-loop reference.

Your exercise

  1. Open monogame-rt4x/FourxGame.MonoGame/Game1.cs. Add fields for a reusable 1x1 pixel texture and for fixed grid dimensions such as 12 columns, 8 rows, and a 48-pixel cell size. Keep them simple constants or readonly fields.
  2. In LoadContent, keep the existing SpriteBatch creation. Then create a 1x1 Texture2D with the current GraphicsDevice and upload a single white pixel using SetData.
  3. Still in Game1.cs, add a small helper that draws one rectangle with the pixel texture. Then add another helper that draws the whole grid by looping over columns and rows and drawing thin vertical and horizontal rectangles.
  4. In Draw, keep GraphicsDevice.Clear, call _spriteBatch.Begin(), draw the grid, then call _spriteBatch.End(). Leave Update almost untouched: the grid is presentation, not simulation.
  5. Center the grid or place it with a deliberate margin. You win when the window shows a stable rectangular playfield instead of only a solid background.

Implementation shape

private Texture2D _pixel;
private const int GridColumns = 12;
private const int GridRows = 8;
private const int CellSize = 48;

protected override void LoadContent()
{
    _spriteBatch = new SpriteBatch(GraphicsDevice);

    _pixel = new Texture2D(GraphicsDevice, 1, 1);
    _pixel.SetData(new[] { Color.White });
}

protected override void Draw(GameTime gameTime)
{
    GraphicsDevice.Clear(Color.CornflowerBlue);

    _spriteBatch.Begin();
    // draw vertical and horizontal line rectangles here
    _spriteBatch.End();

    base.Draw(gameTime);
}

This is not copy-paste homework; it is the minimum skeleton. You still need to decide the grid origin and write the line loops yourself.

Fast feedback

dotnet build monogame-rt4x.slnx
dotnet run --project FourxGame.MonoGame/FourxGame.MonoGame.csproj

Success looks like a blue window with a clearly visible rectangular grid. If the window appears but the grid does not, check four things in order: the pixel texture was created, SetData ran, Begin/End surround the draw calls, and your destination rectangles are on-screen.

Retrieval check

Answer both prompts before opening the answer:

  1. Why can a single 1x1 white texture draw every grid line?
  2. If a future unit moves from one cell to another, which method should change that state: Update or Draw?
Show answers

A 1x1 white texture works because SpriteBatch.Draw can scale it into any destination rectangle and tint it at draw time, so one pixel can become any horizontal or vertical line. A unit's cell change belongs in Update; Draw should only render the current state.
